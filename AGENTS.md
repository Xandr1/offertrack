# AI Agent Instructions

These instructions apply to AI coding agents working in this repository.

## General Rules

- Inspect the current code, tests, configuration, and docs before changing behavior.
- Keep changes small, focused, reviewable, and consistent with existing patterns.
- Do not introduce new libraries, infrastructure, or abstractions unless required by the task.
- Do not change public API, authentication, deployment, or persistence contracts incidentally.
- Do not run long-lived development servers.
- Never claim validation succeeded unless the command was actually run successfully.

## Architecture

OfferTrack contains three applications:

- `apps/web`: Next.js, React, TypeScript, pnpm
- `apps/core-api`: Java 21, Spring Boot, Spring Security, jOOQ, Flyway
- `apps/ai-service`: Python 3.11, FastAPI, Pydantic, OpenAI integration

PostgreSQL and Redis are shared infrastructure. Docker Compose is the local integration environment.

Staging runs on GCP using Terraform-managed Cloud Run services, Cloud SQL, Memorystore, Secret Manager, Artifact Registry, IAM, and Workload Identity Federation. Terraform owns infrastructure shape, IAM, networking, runtime configuration, and secret references. Deployment workflows update immutable images/revisions and traffic.

## Security and Data Rules

- Authentication currently uses signed access JWTs in Secure/HttpOnly cookies. Never store auth tokens in browser storage.
- Preserve CSRF protection, exact CORS behavior, cookie security, protected-profile fail-fast validation, request correlation, and Redis-backed rate limiting.
- Protected environments must fail closed where currently required.
- Never log or expose secrets, tokens, raw rate-limit subjects, or sensitive identifiers.
- Enforce user ownership in backend queries. Missing or foreign user-owned resources should return 404.
- AI service authentication and Cloud Run IAM boundaries must not be weakened.
- Do not commit `.env`, credentials, secret values, or production configuration.

The ADRs in `docs/adr/` describe proposed future architecture. Do not treat them as implemented. Current AI URL validation does not fully prevent DNS rebinding, and current authentication does not provide rotating refresh tokens, server-side sessions, replay detection, logout-all, or general immediate JWT revocation.

## Database and Dependencies

- Use Flyway for schema changes and jOOQ for database access.
- Run `./scripts/backend-codegen.sh` after migration changes.
- Keep pnpm lockfiles generated by the repository-pinned pnpm version.
- Preserve blocking OSV and container vulnerability scanning. pnpm 12 lockfile splitting for OSV is required until the scanner supports the multi-document format directly.

## Validation

Run checks relevant to the changed area:

```bash
pnpm run lint
pnpm run test:web
pnpm run test:api
pnpm run test:ai-service
pnpm run e2e
```

Use `pnpm run test` when full local validation is appropriate.

For infrastructure changes, run the existing Terraform and staging contract validation defined by the repository and preserve immutable-image, IAM, secret, networking, and rollback contracts.

```bash
pnpm --filter web run lint
pnpm --filter web run typecheck
pnpm --filter web run test
```

Backend:

```bash
cd apps/core-api
./mvnw.cmd test
```

Codegen after migrations:

```bash
./scripts/backend-codegen.sh
```
